## What AgroTwin is, in one paragraph

A crop-rotation decision tool for Egyptian farmers (NASA Space Apps 2026, "Field Shift"). Pin a field on the map. AgroTwin
replays every year of real NASA POWER weather since 1991 through an FAO-56 water balance for three rotations: what you
grow now and the two best alternatives. It shows profit, water and risk as ranges, and the Verdex robot's soil readings
narrow this season's range. On top of that sit our own trained model (**Field Pulse**), a **voice assistant** in
Egyptian Arabic, a **time machine** (your field's past seasons read from MODIS), **canal mode** (neighbours plan
together), a 16-day irrigation planner, a backtest, and a validation wall.

## Run it

```bash
cd agrotwin
./run.sh              # http://127.0.0.1:8000 (first run builds ~/.venvs/verdex)
./run.sh offline      # stage mode: cached data only (the Egyptian voice needs internet; the browser voice is the fallback)
make test             # 31 tests
make validate         # qa/REPORT.md
python qa/backtest.py     # qa/BACKTEST.md
python qa/pulse_train.py  # retrain Field Pulse → backend/models/pulse.pkl, qa/PULSE.md
```

The Python env is `~/.venvs/verdex` (3.11). New in 0.5: `scikit-learn`, `edge-tts`, and optionally `faster-whisper`
(its "small" model, ~480 MB, is downloaded the first time someone talks to the assistant).

## Gotchas

- **Never** copy anything from `../farming_robot/` into this repo (camera password in its config).
- Pushing to GitHub over this network: push in chunks with retries (see `AGENTS.md` §5).
- The service worker caches the app shell; bump `SHELL` in `frontend/sw.js` when you add a static file.
- `run.sh offline` never touches the network: `/api/speak` only serves cached MP3s, and new replies use the browser voice.
- Browser speech recognition needs Chrome and an internet connection; otherwise the assistant records audio and uses local Whisper.
- POWER publishes with a few days' lag; MODIS NDVI composites appear about 3 weeks after their start date.
